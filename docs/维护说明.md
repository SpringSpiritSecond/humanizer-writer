# 维护说明

给调这套工作流的人看。只用工作流的人看 [handoff/使用手册.md](../handoff/使用手册.md) 就够了。

## 现在的配置为什么这样定

见 [工作流-当前推荐.md](工作流-当前推荐.md)：每一项决定的依据（四轮盲审）、通用规则，以及还不确定的地方。

## 改配置的地方

| 要改什么 | 改哪里 |
|---|---|
| 模型、skill、一次写几份 | `writer/config.json` |
| 写稿规则（scene-anchored） | `skills/variants/scene-anchored/SKILL.md`。改完要同步到 `handoff/skill/humanizer-writer/references/scene-anchored.md`，有测试会检查两边是否一致 |
| brief 模板 | `writer/brief_template.json`，同样要同步到 skill 的 references |
| 检查规则 | `writer/core.py`（不过/提示的判定）、`detect/`（检测指标） |
| 给 AI 的步骤 | `handoff/skill/humanizer-writer/SKILL.md` |
| 给人的说明 | `handoff/使用手册.md`、`handoff/网页聊天提示词.md` |

## 改之前先评测

换模型、加 skill、改 brief 写法之前，先跑一轮盲审：

1. 在 `eval/arms/*.json` 里写好参赛组合，用 `python eval/scripts/sample_pack.py` 生成稿子（`--samples` 控制每个组合写几份，`--briefs-only` 选题）。
2. 用 `python eval/scripts/build_review_artifact.py --run <目录>` 生成 `<目录>/<名字>-盲审.html`，发给评审，双击就能打开来评。
3. 把评审交回的结果文件放进 `<目录>/ratings/`，再用 `python eval/scripts/reveal.py --run <目录>` 揭晓。

评审由人来做。审稿页上不显示模型、skill 和检测结果，每个人看到的顺序都打乱。

## 仓库里还有什么

| 目录 | 内容 |
|---|---|
| `skills/` | 参加过评测的 skill：`upstream/` 是原版，`variants/` 是改写或自写的 |
| `detect/` | 通用检测：AI 腔句式；感叹句、碎句、口令句的比例；提示词痕迹；口语化；模板句 |
| `eval/` | 盲审工具和评测用的 brief |
| `pipeline/`、`workbench/`、`configs/`、`profiles/` | 早期搭的完整流水线（带自动改稿）和多人工作台，还没接进推荐流程 |
| `docs/` | 调研、流水线设计、当前推荐 |

## 测试

```bash
python -m pytest -p no:cacheprovider --basetemp=<临时目录>
```

部分 Windows 机器上，pytest 默认的临时目录没有写权限，所以要指定 `--basetemp`。
