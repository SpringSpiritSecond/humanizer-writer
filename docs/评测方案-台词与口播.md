# 评测方案：台词与口播两条线并行

- 起草：2026-11-11
- 状态：草案，开跑前要先定下第 7 节的几项
- 前置文档：[课题背景与首轮调研](去AI味-课题背景与首轮调研.md)

这份方案不预先选定 skill。所有候选，包括单独一个 skill 和几个 skill 的组合，都要过同一套评测，最后由人工盲审选出每条线上最好的组合。台词和口播两条线同时做，共用工具和评审流程；brief、淘汰标准和展示方式按线分开。

## 1. 组合怎么拆

一个组合由下面四个槽位各选一项构成。每次只比较同一个槽位里的候选，其余槽位固定。

| 槽位 | 作用 | 台词候选 | 口播候选 |
|---|---|---|---|
| A 生成约束 | 写之前给模型的要求 | 不加；一句话提示；活人感写作；stop-slop；drama-skills 的台词规则；山音写作红线；sw-dialogue | 不加；一句话提示；活人感写作；stop-slop；sean-copy-style 第 1–2 步（文件找回后） |
| B 改写 | 写完后的去 AI 味改写 | 不改；活人感写作；Humanizer-zh；story-deslop；drama-humanizer；qu-ai-wei；说人话 | 不改；活人感写作；Humanizer-zh；qu-ai-wei；说人话；humanizer-zh-next；ai-zixun/humanizer-zh；dsh-deai-audit |
| C 改动范围 | B 能改多大 | 只改原处；限段落；全文 | 同左 |
| D 回合数 | 检测后改写几轮 | 1；最多 3 | 同左 |

候选的出处、许可证和是否能进比赛，登记在 [eval/candidates.csv](../eval/candidates.csv)。本机 `~/.claude/skills/humanizer-zh` 和 op7418/Humanizer-zh 当前的 SKILL.md 逐字相同，算同一个候选。

这些中文 skill 大多是从英文 humanizer 汉化或改写来的，按规则来源大致分三类，比赛时每类至少留一个进第二层：

- **英文规则的汉化**：Humanizer-zh（A–E 组来自 blader v3.0.0，F 组 6 条是中文规则）、humanizer-zh-next
- **受英文启发后的中文重写**：qu-ai-wei、ai-zixun/humanizer-zh、说人话
- **中文原创规则**：活人感写作，以及台词线的 drama-skills、山音

活人感写作在材料不够时会先提问。评测中统一告诉它“不能提问，只用 brief 里的材料”，并留意它因此把稿子写短。长度不合格时要分清原因：是它守规矩不凑字数，还是没完成 brief 的要求。它自带的 `check_prose.py`（MIT）可以拿来参考第一层的结构信号，但是这个脚本出自候选之一，不能拿它来给各家打分。

每条线都有三个固定对照：

- **真人原稿**：判断“像不像人”的锚点
- **AI 原稿**：A、B 都不加，作为“AI 蜜罐”
- **一句话提示**：只在生成时加一句“写得自然，别像 AI”。某个 skill 要是赢不了这一句，就说明它没有用处

## 2. 配对：从真人原稿反推 brief

先收集真人原稿，再从每篇原稿里抽出 brief，交给模型去写。这样 AI 稿和真人稿讲的是同一件事，长度也接近，评审比较的只剩写法。这是 lieflat 第二轮配对复测的思路，我们只借用这个思路，不用它的代码和规则文本。

- **台词**：比较单位是一场戏，时长 1–3 分钟。brief 包括前情、人物卡、这场戏的目标和冲突、beat 列表、必须保留的台词。模型只写对白和动作线。模板见 [eval/briefs/台词/_template.json](../eval/briefs/台词/_template.json)。
- **口播**：比较单位是一条完整口播，时长 30–120 秒。brief 包括产品事实、数字、必须出现的品牌词和 CTA、目标时长、受众。模板见 [eval/briefs/口播/_template.json](../eval/briefs/口播/_template.json)。

每条线收 30 篇真人原稿，其中 20 篇进冻结评测集，10 篇留作之后轮换的新题。

## 3. 第一层：自动淘汰（不花人工）

每个候选在 20 个 brief 上各生成 3 份。生成模型、改写模型、effort 和温度全部固定，只换 skill 文本。输出统一格式：去掉 Markdown，统一标点，台词统一成同一种剧本格式。

这一层只负责淘汰，不负责排名。

| 检查 | 台词 | 口播 | 不过就 |
|---|---|---|---|
| 事实与 beat | beat、人名、道具、锁定台词都还在；没有加 brief 里没有的情节 | 数字、价格、专名、承诺、限定条件逐字一致；没有新增承诺，也没有编出亲历、案例、数字 | 出局 |
| 不该改的不改 | 一组写得好的真人场景，改坏就算失败 | 一组写得好的真人口播，改坏就算失败 | 损坏率超过约定值则出局 |
| 长度 | 和 brief 差 ±20% 以内 | 按自家语速折算成时长，差 ±15% 以内 | 出局 |
| 合规 | 无 | 极限词词典加执法指南豁免 | 出局 |
| 拒答 | 暴力、情感场景的拒答率 | 无 | 记录；过高则出局 |
| 结构信号、LLM 裁判 | 只记录 | 只记录 | 不淘汰、不排名 |

结构信号和 LLM 裁判的分数不用来挑胜者。拿它们挑胜者，skill 会被优化去讨好这些分数，读者的感受就没人管了。这两项分数先存着，等第二层出了人工结果，再看它们和人工判断的一致度。

两条线各自有一项例外，防止误判：

- **台词**：破折号表示打断、角色的口头禅重复、短句、没说完的话，都是正常写法。儿童内容里复述画面的台词也要保留。
- **口播**：设问、三段式、短句重复，是口播的正常手法。

## 4. 第二层：人工盲审，单槽位决出胜者

第一层过关的候选，每个槽位最多留 4 个，进第二层。

每题问两件事，顺序固定：

1. **判别**：“这段像不像 AI 写的？”用 5 档量表，和真人原稿混在一起出。
2. **偏好**：两段并排，“哪段更好？”选项是 A、B、一样好、都不行。台词问“哪段演员更好演、更像人说话”，口播问“哪段你更愿意听完”。

展示方式：

- 统一格式和长度；左右位置每题随机，并记下来
- 来源一律换成不透明 ID，评审始终看不到出处
- 每批混入约 10–15% 的对照题，包括真人锚点、AI 蜜罐、左右调换后重复出的题、明显的金标题
- 台词附上同一张场景卡，所有版本都只有对白不同
- 口播先给文字稿，并请评审读出声。是否改用统一音色的 TTS 音频，见第 7 节

赛制：采用自适应擂台，每轮让当前最好的版本对一个挑战者，明显落后的候选提前停掉，不打全员循环赛。按调研稿的估算，要分辨 65% 对 50% 的胜率，约需 85 票有效票。每个对局按 “3 位评审 × 30 题左右” 准备。结果用 Bradley-Terry 模型算分，置信区间按条目做 cluster bootstrap。

## 5. 第三层：组合

A、B 两个槽位各取前两名，做 2×2 组合，再用最好的组合去试 C、D 的设置。目的是看叠加之后是互相加分，还是一起改过了头。几个 skill 改的是同一类问题时，最容易出现后一种情况。

## 6. 怎么改 skill

1. 评审打的标签，例如“套话”“节奏单一”“不像人说话”，以及过度修改造成的“电报体”（关联词删光，读着断断续续）、“编出来的细节”，加上划出来的片段，汇总成“残留 AI 腔排行”。
2. 把胜出的 skill 复制进本仓库，按排行修改。上游的 skill 不动；每个版本记下 git hash。
3. 新版本作为挑战者，在冻结集上和上一版比。替换条件事先定好：BT 置信区间显示新版不比上一版差，而且被认出是 AI 的比例没有上升。
4. 每跑完一轮，用 10 篇备用题换掉冻结集里的一部分，防止 skill 只对这 20 个 brief 有效。
5. 上游跟进时要复核。blader/humanizer v4.0.0 允许改写时补一个“真实细节”，这条和第一层的事实检查冲突。凡是跟进了这条的候选，事实检查要单独看一遍。

## 7. 开跑前要定的事

| 事项 | 默认做法 | 谁定 |
|---|---|---|
| 真人原稿来源与授权 | 用自家已发布的台词和口播稿 | Ada |
| 固定的生成和改写模型 | 生成用 Claude Opus 5.5，改写用 GLM-5.3，effort 都设为 low | Ada（要开付费 API） |
| 评审是谁、要不要付费 | 从文案、编辑、内容运营同事里招，先过校准题 | Ada（花钱） |
| 口播用文字稿还是 TTS 音频 | 第一轮用文字稿并请评审读出声；音频留到决赛 | Ada |
| 不该改的样本，损坏率上限 | 5% | 先按默认，第一层跑完再看 |
| sean-copy-style 和 zh_slop.py | 找回原文件；找不到就重写 | Ada 找文件，我来重写 |

以下几类事要先问 Ada：花钱、对外发消息、删数据、改课题方向。其余工作，包括跑第一层、改仓库里的 skill 副本、开 PR，可以直接做；最后由盲审结果决定 skill 版本能不能替换。
