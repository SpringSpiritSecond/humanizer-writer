# 去 AI 味写稿工作流：使用手册

适用：任何中文文案，包括台词、科普、口播、带练口令、通知、文章。版本 2026-11-13。

## 这套流程解决什么问题

AI 写的中文常常读着像套话。原因通常不在模型写得差，而在三件事上：

1. **它照着提示词写，不是照着场景写。** 让它“写短点”，它就写成碎句加感叹号；提醒它“不要说 X”，它偏偏去说 X；你强调过的词，它在稿子里一遍遍地重复。
2. **它爱写放进哪篇稿子都成立的句子。** 比如“咱们”“您先放宽心”“心里挺担心的吧”，还有万能开头、空泛鼓励、对旁观者交代情况。
3. **它默认把话往口语、随意那边带。** 但专业的人在工作场合不会这么说话。

经过四轮盲审，我们发现最有用的是**把 brief 写对**，其次是选对模型。加什么 skill 影响不大。依据见 [docs/工作流-当前推荐.md](../docs/工作流-当前推荐.md)。

## 推荐配置

| 项 | 推荐 | 说明 |
|---|---|---|
| 模型 | **Gemini 4 Argon** | 台词两轮第一，科普和 GLM 并列；每份成本约半美分，大约是 Kimi 的 1/8 |
| skill | **scene-anchored**（规则见下文“看稿标准”） | 质量和不加 skill 打平，但能把口语腔和提示词的痕迹压到 0 |
| 不用 | stop-slop | 三轮评测都排在最后 |
| 份数 | 每次写 3 份，人来挑 | 同一个配置写两次，分数可能差 1–2 分 |
| 改稿 | 先不自动改稿 | “先检测再改写”还没有经过评测 |

## 第一步：写 brief

brief 是交给 AI 的材料。**只写场景和事实。**

```
文体：科普 / 台词 / 口播 / 带练口令 / ……
谁在说、对谁说：康复师，对一位家长
在什么场合、两人什么关系：在机构里当面谈；工作关系，第一次长谈
此刻的情况：家长说孩子跳绳总是手脚对不上，问这是怎么回事、在家能做点什么
要讲的事（数字、专名照原样写）：
  - 这项能力叫“双侧整合与交叉”：身体左右两侧配合，手脚越过身体中线去做动作
  - 怎么测：双手打不同节拍、交叉爬、跨过中线指东西
  - 怎么练：异侧拍（左手拍右膝、右手拍左膝）、交叉爬行
长度：约 300 字
格式（可选）：按说话的停顿分段
```

另外单独记一份 **“只用来检查”** 的清单，比如“不能出现：左右脑；不承诺疗效”。**这份清单不交给写稿的 AI**，等稿子写完再拿来对照检查。

写 brief 时，下面三类话不要写进去：

| 不要写 | 为什么 | 改成 |
|---|---|---|
| 风格要求：“要短”“口语一点”“专业一点”“制造紧张感”“语气平实” | AI 会照字面执行。写“要短”，结果写成了碎句 | 写清身份和场合，分寸由场合决定 |
| 强调和反复提醒：“一定要讲清楚是对面的膝盖” | 强调过的词会在稿子里被反复说 | 每件事只写一次 |
| 不能说的话：“不要用左右脑来解释” | 写进去了，AI 反而会去说。试过一次，15 份稿子里 15 份都写了“左右脑” | 放进“只用来检查”的清单 |

台词类 brief 可以写成场景卡：前情、人物（身份、想要什么）、这场戏的目标、冲突、beat。

## 第二步：让 AI 写（三种用法，选一种）

### A. 网页聊天（不用装任何东西）

1. 打开 Gemini 网页版，选 Gemini 4 Argon。其他模型也能用，但我们只验证过这个。
2. 复制 [网页聊天提示词.md](网页聊天提示词.md) 里的整段提示词，把 brief 填进去，发出去。
3. 它会写 3 份。按下面的“看稿标准”挑一份，再对照“只用来检查”的清单看一遍。

### B. 用 Claude Code 或其他 AI 助手（装 skill）

把 [skill/humanizer-writer](skill/humanizer-writer/) 整个文件夹复制到 `~/.claude/skills/` 下，然后直接说“帮我写一段……”。它会：
- 帮你把材料整理成 brief，并把“不能说的”单独拿出来
- 写 3 份。有 Gemini 的 key 时用 Gemini 写
- 逐份检查，给你一份报告

如果直接在这个仓库里打开 Claude Code，不用装，说“按 handoff 里的工作流帮我写……”就行。

### C. 命令行（懂一点代码的人）

在仓库根目录运行：

```bash
python -m writer run --brief 你的brief.json
```

brief 模板是 `writer/brief_template.json`。需要设置环境变量 `RELAYROUTER_BASE_URL` 和 `RELAYROUTER_API_KEY`，用自己或团队的 key，不要互相转发。结果在 `writer/out/` 下：3 份稿子和一份检查报告。详见 [writer/README.md](../writer/README.md)。

## 第三步：挑稿

先排除有硬错误的稿子：
- 出现了“只用来检查”清单里的说法
- brief 里的数字、专名写错了，或者没写
- 多出了 brief 里没有的数字或承诺（换算出来的可以，编出来的不行）

剩下的按看稿标准挑。都不满意的话，**先改 brief**，比如身份、场合、情况写得不够清楚。不要往 brief 里加风格要求。

## 看稿标准：每句话追溯到场景

逐句问：**这句话是说给谁的？回应的是场景里的什么？**

两类句子要删掉，或换成场景里的具体内容：

1. **提示词的痕迹**：写了不让写的；把强调过的反复说；照字面执行风格词；替对方编出他没提过的问题再去回答。
   - 检查方法：光看这句话，能不能猜出提示词里写了什么？
2. **放到哪篇稿子里都成立的句子**：寒暄、安抚、套近乎、空泛的鼓励、万能的开头和收尾、对旁观者交代情况，比如动画里角色互相报告观众已经看见的事。
   - 检查方法：把这句话原样搬到另一份稿子里，还成立吗？

**分寸由场景决定。** 用什么词、什么人称、多正式，都由说话人的身份、场合和与对方的关系来定。专业的人在工作场合说“我们”，话说得清楚、准确；孩子之间说话就是孩子的口吻。关心和着急，靠回应具体的事来体现，不另外加一句表态。

## 还不确定的

- 结论来自一位评审、每个组合 3–6 份稿子，是方向，还不是定论。
- **带练口令**（按节拍喊的跟练口令）用什么配置都只有 2–3 分，目前写出来的还需要人工重写。
- 模型会更新。换模型或改流程之前，先用仓库里的盲审工具（`eval/scripts/`）跑一轮比较。
