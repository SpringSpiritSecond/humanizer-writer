# writer：写稿工作流

一条命令完成：检查 brief → 写 3 份 → 逐份检查 → 出报告，最后由人来挑。适用于任何中文文体。第一次用，先看 [handoff/使用手册.md](../handoff/使用手册.md)。

## 1. 写 brief

复制 [brief_template.json](brief_template.json)，按场景填好。brief 文件放哪都行，建议放在 `writer/briefs/` 下（这个目录里的文件不会被提交）。

| 字段 | 写什么 | 必填 | 注意 |
|---|---|---|---|
| `id` | 这份 brief 的名字，用英文或拼音 | 是 | 输出文件夹会用它命名 |
| `line` | 文体：科普、台词、口播、通知、文章…… | 是 | 只是让模型知道写的是什么，随便写 |
| `speaker` | 谁在说、对谁说、在什么场合、两人什么关系、**听的人有什么特点**（比如“业主里老人多”） | 是 | 说话的分寸（多正式、多口语）由模型从这里推断，**不要写“专业一点”“口语一点”** |
| `situation` | 帮写稿的人理解场景的背景：此刻为什么要说、**之前发生过什么相关的事**（比如“上次停水有人没看到通知”）、对方带着什么问题来 | 建议 | 只写事实。**一件事只放一处**：稿子里必须讲到的放 `facts`，只是背景的放这里 |
| `facts` | 稿子里必须讲到的事，每条一项：`field` 是给你自己看的标签（比如“停水时间”），不会原样进稿子；`value` 是内容，数字和专名照原样写。**真实的安排要写完整**，写稿模型会自己补全没写到的部分 | 是 | 每个数字都会检查有没有写进稿子 |
| `check_only` | 不能出现的说法 | 否 | **写稿模型看不到**，写完才检查，出现就判“不过”。没有就写 `{"不能出现的说法": []}`，不用自己去想 |
| `target.chars` | 目标字数 | 否 | 没有要求就删掉这一项（模板里的 300 只是示例）；写了，偏差超过 30% 会提示 |
| `format` | 交付格式 | 否 | 例如“按停顿分段”“角色名：台词；动作写在括号里”。没有要求就删掉 |

台词也可以用 `scene_card` 写前情、人物、目标、冲突、beat，例子见 [examples/台词-星图暗了.json](examples/台词-星图暗了.json)。其他文体照 [examples/科普-双侧整合.json](examples/科普-双侧整合.json) 写。

以下三类话不要写进 brief：
- **风格要求**：“要短”“制造紧张感”“语气平实”“接地气”。模型会照字面执行，“要短”就被写成过碎句加感叹号。
- **强调和反复提醒**。模型会把强调过的词在稿子里一遍遍地说。
- **不能说的话**。这些放 `check_only`；写进别的字段，模型反而会把它写出来。

## 2. 跑

```bash
python -m writer check --brief writer/examples/科普-双侧整合.json
```

```bash
python -m writer run --brief writer/examples/科普-双侧整合.json
```

- `check` 只检查 brief，不花钱。
- `run` 写 3 份（`--n` 可以改），结果放在 `writer/out/<id>-<时间>/` 下：`稿1.txt`…`稿3.txt`、`report.md`、`report.json`。
- 默认用 Gemini 4 Argon（推荐），需要环境变量 `RELAYROUTER_BASE_URL` 和 `RELAYROUTER_API_KEY`。每份约 1 美分（写稿加检查）。想换模型：复制一份 `config.json`，改掉 `model`（任何 OpenAI 兼容接口都可以），运行时加 `--config <新配置>`。

手上已经有一份稿子，只想检查：

```bash
python -m writer check-text --brief <brief.json> --text <稿子.txt>
```

不想调用模型，加 `--no-model`。这样会跳过“多出来的内容”检查。

## 3. 看报告、挑稿

`report.md` 里每份稿子都附了正文，结论分三档：

- **不过**：出现了 `check_only` 里的说法，或者事实里的数字没写对。这份直接不用。
- **待确认**：稿子里有 brief 没提供的事实、安排或承诺，比如“我们已经张贴了纸质通知”。这一项由模型对照 brief 检查，会多报，也会漏报。
- **通过**：没查出硬问题。

每份还会列一些**提示**：brief 里没有的数字、长度偏差、brief 里的词被反复说、口语化标记偏多、感叹句和碎句偏多、没头没尾的口令、AI 腔句式。没有就写“提示：无”。

“待确认”的内容怎么处理：
- **属实**：补进 `facts`，重跑。
- **不属实，只出现在个别稿子里**：选别的稿子，或者直接在稿子里删掉那句，再用 `check-text` 查一遍。
- **3 份都编了同一件事**：说明读者会自然想到这件事，而 brief 没写清楚。把真实的安排写完整，比如“饮用水放在 3 号楼楼下，由业主自己取”，然后重跑。

检查只能抓硬问题，也会漏报（比如把“周四”说成“本周四”这类推断）。**写得好不好、发出去对不对，由人判断。**

## 4. 配置

[config.json](config.json) 里是模型、写稿规则和份数，这些由维护者调好了，使用时不用改。见 [docs/维护说明.md](../docs/维护说明.md)。
